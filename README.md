# Бот «Банного двора» для MAX

Бронирование бани прямо в мессенджере: гость регистрируется, выбирает баню,
день, процедуры и заход — запись сразу уходит в журнал YCLIENTS.

Телеграм-версия живёт отдельно, в репозитории `barnitsatgbot`. Боты независимы,
но смотрят в один и тот же YCLIENTS.

## Что умеет

* Регистрация гостя: имя и телефон, поиск в базе салона или заведение нового.
* Бронирование: баня → будни/выходные → с процедурами или без → количество
  гостей → банное меню → дата → свободный заход.
* Свободные заходы считаются сами: график бани минус журнал записей.
* Прайс-лист по команде `/price` — фотографии из папок `price` и `menu`.
* Напоминание накануне визита и просьба об отзыве наутро после него.

Бот пишет **только гостю**. Уведомлений о бронях в рабочую группу и сообщений
об ошибках администратору здесь нет — ошибки остаются в логе.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Регистрация |
| `/book` | Забронировать баню |
| `/price` | Прайс-лист |
| `/help` | Помощь и контакты |
| `/cancel` | Отменить текущее действие |

## Запуск

```
pip install -r requirements.txt
python barnitsamaxbot.py
```

Токен бота выдаёт `@MasterBot` в MAX по команде `/newbot`.
Переменные окружения — см. `.env.example`; на хостинге они задаются в панели,
локально кладутся в файл `.env` рядом с ботом.

## Фотографии

* `price/` — листы прайса, уходят первыми;
* `menu/` — банное меню, идут следом.

Порядок внутри папки — по имени файла. Подробности в README каждой папки.

## Что важно знать

**Состояние.** Шаги диалогов, данные гостей и очередь напоминаний лежат в
JSON-файле, путь задаётся переменной `MAX_STATE_FILE`. На хостинге он должен
вести в папку, которая переживает пересоздание контейнера (в BotHost это
`/app/data`), иначе после каждого деплоя гости регистрируются заново,
а напоминания не уходят.

**Таблицы услуг** — `BATHS`, `SERVICE_IDS`, `SERVICE_DURATIONS`, `SEANCE_STARTS`
в начале `barnitsamaxbot.py` — продублированы из телеграм-бота. Меняются цены,
длительность или расписание заходов — правьте в обоих репозиториях, иначе боты
разъедутся и один начнёт предлагать заходы, которых у другого уже нет.

**Часовой пояс.** Все даты и время — по зоне филиала (`TIMEZONE`), а не сервера.
Хостинг вполне может стоять в другой стране, и его дата переключается в другой
момент, чем в бане.

**Долгий опрос.** Обновления забираются через long polling. В документации MAX
он помечен как способ для разработки, а для боевой работы рекомендуется webhook
с HTTPS-сертификатом. Полинг не требует внешнего адреса, поэтому начали с него.
